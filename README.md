# Cookie Cats: полный цикл анализа A/B-эксперимента

**[Страница результатов](https://alex91132.github.io/ab-experiment-loop/)** ·
**[План](PLAN.md)** ·
**[Меморандум](results/memo.md)** ·
[Сайт-портфолио](https://alex91132.github.io/)

Что стоит за решением «перенести ворота в игре или оставить как есть» — от плана
до меморандума с интервалами, guardrails и правилом принятия решения, зафиксированным
**до** анализа.

Игра Cookie Cats (Tactile Entertainment) ставит перед игроком «ворота»: либо ждать,
либо платить. Эксперимент проверяет, что будет, если перенести первые ворота с 30-го
уровня на 40-й. Данные — открытый датасет Kaggle, **90 189 игроков**.

## Результат

| Метрика | Контроль (ворота на 30) | Тест (на 40) | Разница | 95 % ДИ | p |
|---|---:|---:|---:|---|---:|
| Удержание D1 | 44,82 % | 44,23 % | −0,59 п.п. | [−1,24; +0,06] | 0,074 |
| Удержание D7 | 19,02 % | 18,20 % | **−0,82 п.п.** | [−1,33; −0,31] | 0,0016 (Холм 0,0032) |
| Нулевых раундов (guardrail) | 4,33 % | 4,52 % | +0,19 п.п. | [−0,08; +0,46] | — |
| Активное ядро, ≥ 1000 раундов | 0,12 % | 0,14 % | +0,02 п.п. | [−0,02; +0,07] | — |

**Решение: ворота оставить на 30-м уровне** (правило 3 из [PLAN.md](PLAN.md)).
Удержание на 7-й день значимо хуже, и ухудшение (0,82 п.п.) выше чувствительности
эксперимента (MDE 0,7 п.п.) — то есть это не «мало данных», а реальная потеря.

Готовый текст — [results/memo.md](results/memo.md).

## Что делает анализ честным

- **D1 не значим — и это не «победа».** Эффект −0,59 п.п. ниже MDE 0,9 п.п.: эксперимент
  такие эффекты не различает. Так и написано — «недостаточно данных», а не «эффекта нет».
- **Средние раунды врут.** Разница −1,16 раунда исчезает без одного игрока с 49 854 раундами
  (−0,04). Поэтому в отчёте медиана и усечённое среднее, а не только среднее.
- **SRM формально сработал** (χ² = 6,90, p = 0,009), но отклонение от 50/50 всего 0,44 п.п.
  При 90 тыс. игроков значимость ловит любую мелочь — в меморандуме это разобрано отдельно.
- **Правило решения — код, а не мнение.** `src/experiment/decide.py` реализует пять пунктов
  плана; на фактических числах срабатывает правило 3, и это закреплено тестом.

## Структура

```
PLAN.md                  план до анализа: гипотезы, метрики, MDE, правило решения
src/experiment/
  stats.py               доли и интервалы, bootstrap, Холм, границы O'Brien–Fleming
  decide.py              правило принятия решения из плана
  memo.py                генератор меморандума
  format.py              числа в русском формате
scripts/
  fetch_data.py          скачивание CSV с проверкой SHA-256 и числа строк
  run_eda.py             валидация, SRM, профиль раундов → results/eda.json
  run_effects.py         эффекты и guardrails → results/effects.json
  run_memo.py            меморандум → results/memo.md
tests/
  test_stats.py          сверка с известными значениями, свойства, контроль alpha
  test_decide.py         каждое правило на своих данных
  test_claims.py         числа меморандума сверяются с данными
results/                 eda.json, effects.json, memo.md
```

## Запуск

```bash
pip install -r requirements.txt
python scripts/fetch_data.py     # 2,6 МБ, проверка SHA-256
python scripts/run_eda.py
python scripts/run_effects.py
python scripts/run_memo.py
pytest -q                        # 27 тестов
```

## Оркестрация и BI

```bash
docker-compose up -d --build       # Airflow 2.10 + Postgres + Metabase
# Airflow:  http://localhost:8080  (admin / admin), DAG experiment_daily
# Metabase: http://localhost:3000  (analytics@example.com / analytics123)
python scripts/metabase_setup.py    # подключение к analytics, 3 карточки, дашборд
```

DAG `experiment_daily` каждый день пересчитывает контур:

```
ingest → validate → daily_metrics → sequential_monitor → effects → publish_marts → guard_check
```

- `validate` падает при SRM (p < 0,001 и отклонение больше 1 п.п.) или пропусках;
- `sequential_monitor` строит еженедельные взгляды и границы O'Brien–Fleming;
- `publish_marts` пишет витрины в схему `analytics` через `COPY FROM STDIN`;
- `guard_check` падает, если предохранитель сломан — это и есть алерт в UI.

Проверено на живом стеке: прогон DAG — 7 задач, все `success`; в Postgres
`analytics.exp_daily_metrics` (30 строк), `exp_sequential_looks` (6), `exp_effects` (4).

## Чем проверено

- **Статистика:** интервал Уилсона сверен с эталонным значением, z-тест — с ручным расчётом,
  bootstrap воспроизводим по seed, медиана устойчива к выбросу там, где среднее ломается.
- **Последовательный мониторинг:** симуляция 40 000 экспериментов при верной H0 показывает,
  что границы O'Brien–Fleming пересекаются примерно в 5 % случаев — ошибка первого рода
  контролируется не «на глаз».
- **Числа:** `tests/test_claims.py` пересчитывает доли, разницы и SRM прямо из CSV и сверяет
  с меморандумом; если расчёт или форматирование поедут — тест упадёт.
